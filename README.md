# PC Build — подбор комплектующих для компьютера

Практикум «Введение в интернет-технологии», вариант 1 (группа А): сборка конфигурации из нескольких частей, подсчёт итоговой стоимости.

**Адрес приложения:** https://pc-build-dhcj.onrender.com

**Тестовая учётная запись:** логин `testuser`, пароль `test123`

> Приложение работает на бесплатном тарифе Render. После 15 минут без обращений сервис засыпает, первое открытие занимает около минуты. Файловая система бесплатного тарифа не сохраняется между перезапусками, поэтому база создаётся заново при каждом старте: каталог и тестовая учётная запись появляются автоматически, а новые регистрации и заказы после перезапуска пропадают.

## Как запустить

### Через Docker (одинаково на любой машине)

    docker build -t pcbuild .
    docker run --rm -p 8000:8000 pcbuild

Сайт откроется по адресу http://localhost:8000. База создаётся и заполняется при старте контейнера. Чтобы данные сохранялись между запусками, примонтируйте том:

    docker run --rm -p 8000:8000 -v pcbuild-data:/app/data pcbuild

### Без Docker (Windows)

1. Установите Python 3.12 и зависимости: `pip install -r server/requirements.txt`.
2. Запустите `start.bat` (сервер на порту 8000) и откройте http://localhost:8000.
3. Либо откройте папку `web` через Live Server в VS Code: сайт сам найдёт API на `localhost:8000`.

## Настройки (переменные окружения)

- `PORT` — порт сервера (на хостинге подставляется автоматически, по умолчанию 8000).
- `DB_PATH` — путь к файлу SQLite (по умолчанию `server/pcbuild.db`, в Docker `/app/data/pcbuild.db`).
- `DEMO_USERNAME`, `DEMO_PASSWORD` — тестовая учётная запись (по умолчанию `testuser` / `test123`). В базе хранится только хеш пароля.

## Развёртывание на Render

1. Загрузите проект в репозиторий на GitHub (файл базы `*.db` в репозиторий не попадает благодаря `.gitignore`).
2. На render.com: New → Web Service → выберите репозиторий. Язык (Language) — Docker, тариф — Free.
   Либо New → Blueprint: Render сам прочитает `render.yaml`.
3. В поле Health Check Path укажите `/api/health`.
4. После сборки сервис откроется по адресу `https://<имя>.onrender.com`. HTTPS-сертификат Render выдаёт автоматически.

## Структура базы данных (SQLite)

Таблица `users` — пользователи:
- `id` — INTEGER, первичный ключ
- `username` — TEXT, уникальное, от 2 до 12 символов
- `email` — TEXT, уникальный
- `hashed_password` — TEXT, хеш bcrypt

Таблица `products` — товары каталога (21 позиция):
- `id` — INTEGER, первичный ключ
- `name`, `brand`, `category`, `platform` — TEXT
- `price` — INTEGER, цена в рублях
- `image` — TEXT, путь к картинке
- `short_desc`, `description` — TEXT, краткое и полное описание
- `specs` — TEXT, характеристики в формате JSON

Таблица `orders` — позиции заказов:
- `id` — INTEGER, первичный ключ
- `user_id` — INTEGER, внешний ключ на `users.id`
- `product_id` — INTEGER, внешний ключ на `products.id`
- `quantity` — INTEGER, количество
- `created_at` — TIMESTAMP, дата создания

Связи: один пользователь — много заказов, один товар — много заказов. Все SQL-запросы параметризованные.

## API

- `GET /api/health` — проверка работоспособности
- `GET /api/products` — список товаров
- `GET /api/products/{id}` — один товар
- `POST /api/register` — регистрация
- `POST /api/login` — вход
- `POST /api/forgot-password` — восстановление пароля (заглушка)
- `POST /api/orders` — создание заказа
- `GET /api/orders` — все заказы (для отладки)
- `GET /api/my-orders?user_id=` — заказы пользователя

## Что сделано

- ПР 1: 8 страниц на семантической разметке, Flexbox и Grid, адаптивная вёрстка от 360 px, 21 товар в каталоге.
- ПР 2: формы с валидацией, фильтры и сортировка без перезагрузки, карта на Nominatim и Leaflet с индикатором загрузки и обработкой ошибок сети.
- ПР 3: сервер на FastAPI, база SQLite из трёх связанных таблиц, пароли в виде хеша bcrypt, страница «Мои заказы» для вошедших пользователей.
- ПР 4: Dockerfile, настройки в переменных окружения, сервер отдаёт и API, и страницы с одного адреса, развёртывание на Render по HTTPS.
